# ربات SUI

[English](README.md) | [فارسی](README.fa.md)

ربات SUI یک ربات مدیریتی تلگرام برای پنل [S-UI](https://github.com/alireza0/s-ui) است. مدیران می‌توانند کاربران پنل را از داخل تلگرام مدیریت کنند و هر کاربر نیز اشتراک، میزان مصرف، لینک‌ها و گزینه‌های تمدید خود را ببیند.

## امکانات

- ساخت، ویرایش، فعال‌سازی، غیرفعال‌سازی و حذف کاربران S-UI.
- اتصال یک یا چند اشتراک به هر حساب تلگرام.
- نمایش مصرف، تاریخ انقضا، وضعیت، لینک‌های اشتراک و لینک پنل وب.
- امکان واردکردن آزادانه نام گروه هنگام ساخت یا ویرایش کاربر.
- مدیریت طرح‌های تمدید، رسید پرداخت، تأیید و رد درخواست.
- نمایش درست شماره کارت از چپ به راست در تمام زبان‌ها و امکان کپی با لمس خود شماره.
- ارسال پیام همگانی و یادآوری انقضای اشتراک.
- تهیه نسخه پشتیبان محدودشده از نظر حجم و نمایش وضعیت سرور.
- خروجی و بازیابی اتصال‌ها، زبان کاربران، آمار، تنظیمات زمان اجرا و حافظه‌های کش در یک فایل اعتبارسنجی‌شده.
- پشتیبانی مستقل از زبان‌های انگلیسی، فارسی، روسی و چینی برای هر حساب تلگرام.
- امکان شخصی‌سازی نام استفاده‌شده در پیام‌های ربات، بدون تغییر نمایه تلگرام.
- امکان حذف اختیاری پورت از لینک‌های اشتراک کاربران، پس از هشدار و تأیید تنظیم reverse proxy.
- اجرای دائمی به‌صورت یک سرویس سخت‌سازی‌شده systemd.
- فرمان سراسری `sui-bot` برای مدیریت ربات از هر مسیر ترمینال.

## پیش‌نیازها

- سرور لینوکسی دارای systemd.
- دسترسی root یا `sudo`.
- پنل فعال S-UI و توکن مدیر پنل.
- توکن ربات تلگرام از BotFather.
- HTTPS برای پنل S-UI که روی میزبان راه‌دور قرار دارد.

در توزیع‌های پشتیبانی‌شده، نصب‌کننده Python، محیط مجزای Python، بسته‌های موردنیاز و Git را نصب یا پیکربندی می‌کند.

Redis اختیاری است و به‌طور پیش‌فرض غیرفعال است؛ بنابراین نصب معمولی هشدار اتصال Redis تولید نمی‌کند. فقط زمانی `REDIS_ENABLED=true` را تنظیم کنید که یک سرور Redis قابل‌دسترسی پیکربندی شده باشد.

## نصب با یک فرمان

فرمان زیر را اجرا کنید:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/Sownix21/SUI-Bot/main/scripts/install.sh | sudo bash
```

نصب‌کننده فقط این موارد را درخواست می‌کند:

1. نشانی پنل S-UI، مانند `https://panel.example.com`.
2. توکن مدیر S-UI.
3. توکن ربات تلگرام.
4. شناسه تلگرام مدیر.

نیازی به واردکردن آدرس اشتراک یا تنظیم دستی ورودی‌ها نیست. ربات SUI در هر بار راه‌اندازی درخواست احرازشده زیر را ارسال می‌کند:

```text
GET <SUI_HOST>/apiv2/load
Token: <SUI_TOKEN>
```

ربات مقادیر `obj.subURI` و `obj.inbounds` را استخراج و ذخیره موقت می‌کند و برای ساخت لینک‌های اشتراک و منوهای کاربران به کار می‌برد. سایر بخش‌های پاسخ، از جمله تنظیمات حساس پنل، ثبت یا ذخیره نمی‌شوند.

سپس نصب‌کننده:

- کاربر سیستمی محدودشده `sui-bot` را می‌سازد؛
- برنامه را در `/opt/sui-bot` نصب می‌کند؛
- محیط اختصاصی Python را در `/opt/sui-bot/.venv` می‌سازد؛
- اطلاعات محرمانه را در `/etc/sui-bot/sui-bot.env` نگه می‌دارد؛
- مسیر قابل‌نوشتن `/var/lib/sui-bot` را برای داده‌ها می‌سازد؛
- سرویس `sui-bot.service` را نصب و فعال می‌کند؛
- فرمان `/usr/local/bin/sui-bot` را نصب می‌کند تا منوی مدیریت از هر مسیری قابل اجرا باشد.

## اولین اجرا در تلگرام

ربات را باز کنید و فرمان زیر را بفرستید:

```text
/start
```

در اولین اجرا، هر حساب—از جمله مدیر—باید یکی از زبان‌های انگلیسی، فارسی، روسی یا چینی را انتخاب کند. زبان بعداً از دکمه «زبان» قابل تغییر است.

زبان انتخاب‌شده در تمام رابط تلگرام اعمال می‌شود: منوها و فرایندهای مدیر، صفحات اشتراک و تمدید کاربران، دکمه‌ها، پیام‌های اعتبارسنجی و خطا، یادآوری‌ها، گزارش‌ها، پیام‌های نسخه پشتیبان و کپشن‌ها. نام‌ها، توضیحات، شناسه‌ها و فرمان‌هایی که مستقیماً از سرور دریافت می‌شوند بدون تغییر باقی می‌مانند. نشانی‌ها نیز تغییر نمی‌کنند، مگر اینکه مدیر گزینه حذف پورت لینک اشتراک را که در ادامه توضیح داده شده است، صریحاً فعال کند.

مدیر می‌تواند از مسیر **تنظیمات ← تنظیم نام نمایشی پیام‌ها** برند ربات را تغییر دهد. این گزینه فقط نام نوشته‌شده در پیام‌های تولیدشده توسط ربات را عوض می‌کند و هرگز نام نمایه تلگرام یا `@username` را تغییر نمی‌دهد؛ این موارد دقیقاً مطابق تنظیمات BotFather باقی می‌مانند. نام سرویس لینوکس و مسیرهای داده نیز همچنان `sui-bot` خواهند بود.

گزینه مخصوص مدیر **حذف پورت از لینک‌های اشتراک** می‌تواند لینک‌هایی مانند `https://example.com/path/user/` را به‌جای `https://example.com:2096/path/user/` به کاربران نشان دهد. فعال‌سازی آن فقط پس از نمایش هشدار و تأیید جداگانه انجام می‌شود. ابتدا nginx یا reverse proxy دیگر یا مسیریابی معادل را طوری تنظیم کنید که درخواست بدون پورت به سرویس اشتراک S-UI برسد؛ در غیر این صورت لینک‌های بازنویسی‌شده کار نخواهند کرد. ربات nginx یا سرور S-UI را تغییر نمی‌دهد.

پیام‌های یادآوری انقضا دارای دکمه مستقیم تمدید هستند. برای یک اشتراک در حال انقضا یک دکمه و برای چند اشتراک در حال انقضا یک دکمه جداگانه برای هر اشتراک نمایش داده می‌شود.

کاربری که فقط یک اشتراک دارد دکمه «اشتراک من» را می‌بیند و مستقیماً وارد همان اشتراک می‌شود. دکمه «اشتراک‌های من» و بازگشت به فهرست اشتراک‌ها فقط برای کاربران دارای چند اشتراک نمایش داده می‌شود.

## مدیریت ربات

فرمان زیر را از هر مسیری اجرا کنید:

```bash
sudo sui-bot
```

منوی تعاملی امکانات زیر را دارد:

- نمایش وضعیت سرویس؛
- شروع، توقف یا راه‌اندازی مجدد ربات؛
- نمایش گزارش‌های اخیر یا دنبال‌کردن زنده گزارش‌ها؛
- تغییر اطلاعات ورود و تنظیمات اجرایی؛
- اعتبارسنجی پیکربندی؛
- بررسی فایل‌های اتصال و داده؛
- دریافت و نصب آخرین نسخه از GitHub؛
- حذف کامل ربات.

فرمان‌های مستقیم نیز در دسترس هستند:

```bash
sui-bot status
sudo sui-bot start
sudo sui-bot stop
sudo sui-bot restart
sui-bot logs -n 200
sui-bot logs --follow
sudo sui-bot config
sui-bot show-config
sui-bot validate
sudo sui-bot doctor
sudo sui-bot update
sudo sui-bot uninstall
```

## پشتیبان‌گیری و بازیابی اطلاعات ربات

فقط مدیر تلگرام تعریف‌شده در پیکربندی می‌تواند نسخه پشتیبان بسازد یا بازیابی کند.

برای ساخت نسخه پشتیبان:

1. در منوی مدیر تلگرام وارد **تنظیمات** شوید.
2. **پشتیبان‌گیری و بازیابی** را انتخاب کنید.
3. **ساخت و ارسال پشتیبان** را انتخاب کنید.
4. فایل دریافتی با پسوند `.sui-backup.json` را محرمانه نگه دارید.

این فایل شامل اتصال کاربران، زبان انتخابی حساب‌های تلگرام، آمار، تنظیمات تمدید و پرداخت، حافظه کش اشتراک و ورودی‌ها و وضعیت اعلان‌های انقضا است. خلاصه‌ای غیرمحرمانه از پیکربندی نیز در آن قرار می‌گیرد. `BOT_TOKEN` و `SUI_TOKEN` عمداً در فایل قرار نمی‌گیرند، زیرا فایل ارسالی در تلگرام نباید دارای اطلاعات ورود قابل‌استفاده مجدد باشد.

برای بازیابی فایل، فرمان زیر را بفرستید:

```text
/restore
```

سپس فایل پشتیبان را به ربات ارسال کنید. پیش از جایگزینی اطلاعات، ربات شناسه مدیر، محدودیت حجم ۱۰ مگابایت، نسخه قالب، checksum از نوع SHA-256، بخش‌های مجاز، شناسه اتصال‌ها، کدهای زبان و کلیدهای تنظیمات زمان اجرا را بررسی می‌کند. اتصال‌ها و تنظیمات بازیابی‌شده بلافاصله بارگذاری می‌شوند. برای خروج بدون تغییر اطلاعات از `/cancel` استفاده کنید.

## بروزرسانی بدون ازدست‌رفتن اطلاعات

برای نصب‌هایی که از مسیرهای فعلی ربات SUI استفاده می‌کنند، فرمان زیر را اجرا کنید:

```bash
sudo sui-bot update
```

بروزرسانی برنامه و محیط مجزای Python را جایگزین می‌کند، اما موارد زیر حفظ می‌شوند:

- `/etc/sui-bot/sui-bot.env`
- `/var/lib/sui-bot`
- اتصال‌ها، زبان‌ها، حافظه‌های کش، آمار، تنظیمات و نسخه‌های پشتیبان داخل مسیر داده

در بروزرسانی‌های بعدی نیازی به انتقال دوباره این فایل‌ها ندارید.

### انتقال یک‌باره از ساختار نصب قدیمی

ساختار قدیمی سرویس از مسیر داده دیگری استفاده می‌کرد. نصب نسخه جدید، آن مسیر را به‌صورت خودکار با `/var/lib/sui-bot` ادغام نمی‌کند. اگر اطلاعات شما هنوز در `/var/lib/obscura-bot` قرار دارد، این انتقال یک‌باره را انجام دهید:

```bash
sudo systemctl disable --now obscura-bot.service
sudo systemctl stop sui-bot.service
sudo cp -a /var/lib/obscura-bot/. /var/lib/sui-bot/
sudo chown -R sui-bot:sui-bot /var/lib/sui-bot
sudo chmod -R u+rwX,g+rX,o-rwx /var/lib/sui-bot
sudo systemctl restart sui-bot.service
sudo sui-bot doctor
```

این کار را پیش از ساخت اتصال‌های جدید انجام دهید، زیرا کپی مسیر قدیمی ممکن است فایل‌های جدیدتر را بازنویسی کند. پس از قرارگرفتن داده‌ها در `/var/lib/sui-bot`، بروزرسانی‌های آینده آن‌ها را خودکار حفظ می‌کنند.

## فایل‌ها و مسیرهای مهم

| مسیر | کاربرد |
| --- | --- |
| `/opt/sui-bot` | برنامه نصب‌شده و محیط مجزای Python |
| `/etc/sui-bot/sui-bot.env` | اطلاعات ورود و پیکربندی محافظت‌شده |
| `/var/lib/sui-bot/assignments.json` | اتصال حساب‌های تلگرام به کاربران S-UI |
| `/var/lib/sui-bot/backups` | نسخه‌های پشتیبان دریافت‌شده از پایگاه داده |
| `/var/lib/sui-bot/user_languages.json` | زبان انتخابی هر حساب |
| `/var/lib/sui-bot/runtime_settings.json` | تنظیمات نام نمایشی، تمدید و پرداخت |
| `/var/lib/sui-bot/subscription_cache.json` | آخرین نشانی معتبر اشتراک S-UI |
| `/var/lib/sui-bot/inbounds_cache.json` | آخرین فهرست معتبر ورودی‌ها |
| `/etc/systemd/system/sui-bot.service` | فایل تعریف سرویس systemd |
| `/usr/local/bin/sui-bot` | فرمان سراسری مدیریت |

هنگام اجرا توسط systemd، مسیرهای نسبی داده در زیر `/var/lib/sui-bot` قرار می‌گیرند.

## پیکربندی

تنظیمات الزامی عبارت‌اند از:

| تنظیم | توضیح |
| --- | --- |
| `SUI_HOST` | نشانی پایه پنل S-UI |
| `SUI_TOKEN` | توکن مدیر S-UI |
| `BOT_TOKEN` | توکن ربات تلگرام |
| `ADMIN_TELEGRAM_ID` | شناسه تلگرامی که اجازه استفاده از امکانات مدیر را دارد |

مقادیر اختیاری در فایل [.env.example](.env.example) مستند شده‌اند. ساده‌ترین راه تغییر تنظیمات پس از نصب:

```bash
sudo sui-bot config
```

هنگام نمایش پیکربندی، توکن‌ها مخفی می‌شوند. فایل محیط به‌صورت اتمیک و با سطح دسترسی `0600` نوشته می‌شود.

نشانی پنل S-UI راه‌دور باید از HTTPS استفاده کند. HTTP فقط برای نشانی‌های loopback به‌طور خودکار پذیرفته می‌شود. گزینه `ALLOW_INSECURE_HTTP=true` برای شبکه خصوصی قابل‌اعتماد وجود دارد، اما نباید روی اینترنت عمومی استفاده شود.

## رفع اشکال

وضعیت سرویس و گزارش‌های اخیر را بررسی کنید:

```bash
systemctl status sui-bot.service
journalctl -u sui-bot.service -n 200 --no-pager
```

برای مشاهده زنده گزارش‌ها:

```bash
journalctl -u sui-bot.service -f
```

پیکربندی و مسیرهای داده را اعتبارسنجی کنید:

```bash
sudo sui-bot validate
sudo sui-bot doctor
```

اگر فایل‌های منتقل‌شده قابل خواندن یا نوشتن نیستند:

```bash
sudo chown -R sui-bot:sui-bot /var/lib/sui-bot
sudo chmod -R u+rwX,g+rX,o-rwx /var/lib/sui-bot
sudo systemctl restart sui-bot.service
```

اگر لینک اشتراک یا ورودی‌ها در دسترس نیستند، مطمئن شوید `SUI_HOST` قابل‌دسترسی است و `SUI_TOKEN` اجازه فراخوانی `/apiv2/load` را دارد.

گزارش یادآوری، اشتراک‌هایی را که نزدیک انقضا هستند اما به تلگرام متصل نشده‌اند مشخص می‌کند. هر مورد شامل توضیح، نام کاربری S-UI، شناسه کاربر و روزهای باقی‌مانده است تا مدیر بتواند آن را با `/assign` متصل کند.

## نکات امنیتی

- callbackهای غیرمدیر به‌جز مواردی که صریحاً مجاز شده‌اند رد می‌شوند.
- هر کاربر فقط به شناسه‌هایی دسترسی دارد که به حساب تلگرام او متصل شده‌اند.
- نشانی HTTP راه‌دور برای S-UI به‌طور پیش‌فرض رد می‌شود.
- پاسخ‌های API محدودیت حجم و timeout اتصال و خواندن دارند.
- پاسخ کامل `/apiv2/load` هرگز ثبت یا ذخیره نمی‌شود.
- اطلاعات محرمانه در فایل محیط محافظت‌شده باقی می‌مانند.
- سرویس systemd با حساب بدون دسترسی ویژه و تنظیمات سخت‌سازی فایل‌سیستم اجرا می‌شود.
- دریافت نسخه پشتیبان دارای سقف حجم قابل تنظیم است.

هرگز توکن S-UI، توکن تلگرام، کلید خصوصی TLS یا پاسخ کامل `/apiv2/load` را منتشر نکنید.

## حذف کامل

فرمان زیر را اجرا کنید:

```bash
sudo sui-bot uninstall
```

برای تأیید باید عبارت `UNINSTALL SUI BOT` را دقیقاً وارد کنید. حذف کامل، برنامه، سرویس، پیکربندی، کاربر سیستمی، اتصال‌ها، تنظیمات و نسخه‌های پشتیبان را پاک می‌کند. پیش از تأیید، از هر موردی که می‌خواهید نگه دارید کپی بگیرید.

## توسعه محلی

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
# فایل .env را ویرایش و سپس ربات را اجرا کنید:
python -m sui_bot
```

فرمان فعال‌سازی در PowerShell برابر `.venv\Scripts\Activate.ps1` است.

بررسی‌ها را با این فرمان‌ها اجرا کنید:

```bash
python -m compileall -q src
ruff check src tests
pytest
```
